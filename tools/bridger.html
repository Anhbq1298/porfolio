Bridger

Moves parts of one ETABS model into another — geometry, names, assignments and definitions intact — and verifies every value against the target model.

Problem

Design teams often develop parts of a building in separate ETABS models and later need to merge them. Copying objects by hand loses unique names and assignments, and re-applying sections, releases, springs, loads and labels is slow and easy to get wrong.

How it works

Methodology

  • Connect. Attach to two running ETABS instances (source and target), found by process and attached by PID.
  • Select. Pick joints, frames and shells in Model A and tick the categories to migrate.
  • Migrate in stages. Geometry and names → section definitions → assignments → loading → pier and spandrel labels → design overwrites.
  • Fixed rules, no prompts. Each situation — no match, one match, several matches, name taken — has a defined behaviour; skipped items are logged.
  • Verify. Every value is read back from Model B and compared before the model is refreshed.

Result

Model merges become repeatable and auditable: what was copied, reused, renamed or skipped is recorded in a log rather than relying on manual checks.

Technical implementation

  • .NET 8 WPF application compiled against the ETABS API.
  • Load patterns, cases (including nonlinear static, staged construction and time history) and combinations migrate with the functions and mass sources they depend on.
  • Live test suite drives two ETABS instances and regenerates a capability matrix of verified categories.

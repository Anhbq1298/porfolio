MGT

Problem

Architectural geometry lives in Rhino, analysis lives in ETABS or SAP2000. Rebuilding irregular geometry in the analysis model, and keeping it in sync as the design changes, is slow and repetitive.

Methodology

  • CSI link. Components wrap the ETABS and SAP2000 APIs to set up, edit, query and load models from Grasshopper, and export data trees to Excel.
  • Grillage builder. Turns slab boundaries into a strut-and-tie grillage model by conditionally sorting the Grasshopper data tree.
  • Tributary take-down. Voronoi-based tributary areas for irregular wall and column layouts from cleaned CAD data.

Result

Analysis models are generated and updated parametrically from the design geometry instead of being redrawn by hand.

Technical implementation

  • Grasshopper 8 plugin in C#, organised by component family (units, materials, loadings, points, frames, shells, cables, utilities).
  • Python 3 components for data-tree processing.
  • Compatibility and domain tests; example definitions shipped with the plugin.

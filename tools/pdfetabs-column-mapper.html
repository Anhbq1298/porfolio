PDFETABS Column Mapper

Faster, more reliable column naming for CORENET X submissions — matches PDF markup tags to ETABS columns and gives engineers a visual QA/QC overlay before names are written back.

Problem

For CORENET X submission, column names in the analysis model must match the drawings exactly. Renaming hundreds of columns by hand from marked-up PDFs is slow, and a single mismatch between drawing and model creates rework at submission.

Methodology

  • Read both sources. Column tags and page scale come from the marked-up PDF; columns by story come from ETABS through the API.
  • Common origin. The engineer pins one PDF tag to one ETABS constraint column so both sets share a local frame.
  • Geometric matching. Each ETABS column searches for PDF tags within a set radius and is classified as Match, Ambiguous, No match or Conflict.
  • Review. An overlay chart and column inspector show every pairing; engineers can overwrite manually.
  • Write back. Names are applied with a two-pass rename and pier labels are assigned; a report is exported for QA/QC.

Result

Naming becomes a visual check rather than a manual transcription: discrepancies between drawings and model are visible before anything is written to ETABS.

Technical implementation

  • ETABS API for reading columns by story and writing names and pier labels.
  • PDF annotation parsing with page and scale handling.
  • Interactive overlay chart with search radii, match lines and status filtering.
